# Session 23 model answer: Cost, latency and reliability engineering

Open only after the learner has attempted the case in their own words.

## Case

A nightly job summarising 40,000 tickets costs too much and sometimes fails on rate limits at peak.

## Model answer

Move it to the Batch API with a cached shared prefix, send simple tickets to a smaller model once an eval shows it holds, cap output length, add retries with backoff and track cost per ticket from the usage fields.
