# Session 16: Capstone and staying current

Level 4: Operator (75 to 100). Deliverable: Capstone and handover doc. Worth: 5 points. This is a gate.

Contents: Goal and outcomes, Key points, Plain-language glossary, Capstone options, The handover doc, The monthly routine, Model lifecycle, Worked demo: capstone day, Common mistakes, Cheat sheet, Exercises, Case to attempt, Vocabulary, Score ladder (what your work looks like at each level), Going further, Study sources, Self-check questions, Exit ticket.

## Goal and outcomes

**Goal.** The learner ships a capstone and sets up the habit that keeps the skills current.

**You will be able to:**
- Deliver a capstone with its eval, cost note and handover doc
- Defend each design choice: model, effort, skills, connectors, permissions
- Run a monthly update routine

## Key points

- Capstone options: (A) an operations agent team for a real workflow, with approvals; (B) a plugin of three or more skills and connectors for a team; (C) a tool built in Claude Code with tests, hooks and a scheduled run.
- Handover doc: purpose, inputs and outputs, models and effort, skills, connectors and permissions, eval results, cost per run, known failure modes, owner and how to update it.
- Models have a lifecycle of active, deprecated or retired, which the List Models endpoint reports for each model. Check it for every model your tools call.
- Features change monthly, and menu names already differ between documentation pages, so check the live interface and the release notes before relying on a feature.
- Monthly routine: read the release notes, check lifecycle of every model in use, rerun the evals if a model changed, update the course key points, and review permissions on connectors and plugins.

1. Purpose
2. Inputs and outputs
3. Models and effort

9. Owner

Someone else must be able to run and update the work from this page.

## The monthly routine

1. Read the release notes.
2. Check the lifecycle of every model in use.
3. Rerun the evals if a model changed.
4. Update the key points you teach.
5. Review permissions on connectors and plugins.

Schedule it as a recurring task.

## Model lifecycle

| Status | Do |
|---|---|
| Active | Keep using; check monthly |
| Deprecated | Read the retirement date, run your eval on the replacement, then switch |
| Retired | Calls fail: fix at once |

The List Models endpoint reports each model's lifecycle. Check every model your tools call.

Features change monthly. Check the live interface and the release notes.

## Common mistakes

| Mistake | Why it happens | Fix |
|---|---|---|
| Building before writing criteria | There is nothing to judge against | Write measurable criteria first |
| No cheaper model tested | The model choice cannot be justified | Test one cheaper option and report the result |
| A handover only the author can use | It fails on the day someone else runs it | Ask a colleague to update it from the doc alone |
| Never rechecking models | A retired ID breaks the build | Run the monthly routine |
