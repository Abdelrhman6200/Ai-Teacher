# Session 4: Prompting that meets success criteria

Level 2: Practitioner (25 to 50). Deliverable: Prompt library: 5 before and after pairs with criteria and scores. Worth: 6 points.

Contents: Goal and outcomes, Key points, Plain-language glossary, A weak prompt made strong, Tags and examples, Long inputs, Is it the prompt?, Worked demo: the email prompt, Common mistakes, Cheat sheet, Exercises, Case to attempt, Vocabulary, Score ladder (what your work looks like at each level), Going further, Study sources, Self-check questions, Exit ticket.

## Goal and outcomes

**Goal.** The learner writes prompts that produce usable output the first time, and tests them against criteria.

**You will be able to:**
- Write success criteria before writing the prompt
- Apply the core techniques: clear and direct, context and motivation, examples, XML structure, role, long-context placement, output format
- Decide whether a problem needs a better prompt, a different effort level or a different model
- Turn a working prompt into a reusable template with variables

## Key points

- Be clear and direct. Test: could a colleague with minimal context follow the prompt?
- Explain why a constraint matters so Claude can generalise from it.
- Use 3 to 5 relevant, diverse examples wrapped in example tags to steer format, tone and structure.
- Wrap instructions, context, examples and inputs in consistent XML tags.
- One sentence of role focuses tone and behaviour.
- For inputs over 20k tokens, put the documents first and the question last, and ask Claude to quote the relevant passages first.
- Say what to do, not what to avoid.
- Prefer general guidance such as "think thoroughly" to hand-written step lists, and adjust effort for depth.
- Be explicit about action: "can you suggest changes" gets suggestions, "change this function" gets edits.
- Before prompt engineering you need success criteria, a way to test them and a first draft. Prompting fixes only what the prompt controls; some problems need a different model.
- Prefilling the last assistant turn returns an error from Claude 4.6 onward, so on the whole Claude 5 family. Put format, preamble and continuation rules in the instructions instead. On the newer models do not ask for reasoning in thinking tags: the request may be declined, the models think on their own, and effort controls how much.
(from the prompting best practices)

## Plain-language glossary

| Term | Meaning | Think of it as |
|---|---|---|
| Prompt | Everything you give the model: request, context, examples, inputs | A brief to a capable new colleague |
| Success criteria | What a good answer must contain, written before you prompt | The marking scheme |
| Example | A sample of the output you want | Make it like this one |
| Tags | Named labels wrapped around each part of a prompt | Folders that keep rules, documents and question apart |
| Output format | The shape of the answer: table, list, fixed fields | The template the reader expects |

## A weak prompt made strong

| Part | What the strong prompt adds |
|---|---|
| Reader | A manager with two minutes |
| Goal | Decide whether to approve the budget |
| Shape | Three bullets: finding, risk, decision needed |
| Evidence | The page number for every figure |
| Style | Plain language, no jargon |

Weak version: 'Summarise this report.'

Show the weak and the strong version side by side in Claude and compare the outputs.

## Tags and examples

- <instructions>: the task and the reason behind each constraint
- <example>: one good output; use 3 to 5 diverse ones
- <document>: the input; for inputs over 20k tokens put documents first
- <format>: the shape of the output
- Use the same tag names every time so the structure stays predictable.

Tags show Claude where each part starts and ends. Run the example ladder (0, 1, 3 examples) after this.

## Long inputs

1. Put the documents first.
2. Put your instructions next.
3. Put the question last.
4. Ask Claude to quote the relevant passages before it answers.

Applies to any input over about 20k tokens.

## Is it the prompt?

| Symptom | Likely cause | Try |
|---|---|---|
| Format drifts between runs | No example to copy | Add 3 to 5 examples in example tags |
| Answer is generic | Reader, goal or tone missing | State them and give a sample of the voice |
| Misses a detail in a long document | Question buried, no quoting | Documents first, question last, quote first |
| Still wrong after a clear prompt | A model or effort limit | Raise effort or move up a tier (session 3) |

Prompting fixes only what the prompt controls.

## Worked demo: the email prompt

Run this yourself on your own material.

| Step | Do this | What it shows |
|---|---|---|
| 1 | Start with the weak prompt: make this email better | Generic output, because nothing defines better |
| 2 | Add reader, goal, tone, length and what must stay | Each detail removes a guess |
| 3 | Add one short example of the voice wanted, inside example tags | An example steers tone and format more than adjectives |
| 4 | Score both versions against three written criteria | Improvement is shown by scores, not by feel |

## Common mistakes

| Mistake | Why it happens | Fix |
|---|---|---|
| A vague request | Claude picks the likeliest reading | Name audience, purpose and format |
| Rules with no reasons | Claude cannot extend them to cases you did not list | Add a clause saying why the rule matters |
| Saying what not to do | A negation leaves the target open | Say what to do instead |
| Fixing a model limit with wording | Some failures are not controlled by the prompt | Check prompt, then effort, then model |

## Cheat sheet

**Know**
- Success criteria first, then the prompt.
- Be clear and direct, and give the reason for each rule.
- 3 to 5 diverse examples, XML tags, one line of role.
- Long input: documents first, question last.

**Do**
- Write three criteria for the task.
- Rewrite the prompt and run both versions.
- Score against the criteria.
- Turn the winner into a template with variables.

## Exercises

1. Rewrite lab. Take five weak prompts from the learner's work, write 3 criteria for each, rewrite, run both versions and score against the criteria.
2. Example ladder. Run one task with 0, 1 and 3 examples and compare how consistent the format is.
3. Template. Turn the best prompt into a template with variables inside XML tags.

## Going further

- The colleague test: could someone with minimal context follow this prompt and produce what you want?
- Use 3 to 5 examples that differ from each other, so Claude learns the pattern and not one case.
- For inputs over 20k tokens, put the documents first and the question last, and ask for the relevant quotes before the answer.
- Turn every winning prompt into a template with variables and test it again whenever the model changes.
