## Goal and outcomes

**Goal.** The learner configures a project so rules are enforced, work is delegated and runs can happen unattended.

**You will be able to:**
- Write a subagent with scoped tools and a model
- Write a hook that blocks an action and a hook that runs a check
- Run Claude headless with limits
- Add a project skill and an MCP server, and see their cost in context

## Key points

- Subagents are Markdown files with YAML frontmatter in .claude/agents/ (project) or ~/.claude/agents/ (all projects). name and description are required; tools restricts what it can use; model accepts sonnet, opus, haiku, fable, a full ID or inherit.
- A subagent runs in its own context window and only a summary returns. It starts fresh, without your conversation, so the delegation prompt must carry what it needs. Each subagent's requests count toward usage. Built in: Explore (read-only), Plan and general-purpose.
- Hooks run at lifecycle events such as PreToolUse, PostToolUse, UserPromptSubmit and Stop, configured in settings.json at user, project or local level. Exit code 2 blocks a PreToolUse action. A Stop hook sends Claude back to work when its script exits with 2. A hook cannot undo a PostToolUse, because the tool already ran.
- CLAUDE.md tells Claude what to do and Claude decides; hooks guarantee that something happens or does not. For hard allow and deny rules the docs recommend the permission system, since hook filters are best-effort.
- A skill lives at .claude/skills/name/SKILL.md. Setting disable-model-invocation to true makes a side-effect workflow, such as a release, run only when you type it.
- Add an MCP server from the shell with claude mcp add. Connected servers add their tool names to context even when unused, so disable what you do not need under /mcp.
- claude -p runs one prompt non-interactively, accepts piped input and JSON output, and takes limits such as --max-turns and --max-budget-usd. It also runs in CI through GitHub Actions.

## A subagent file

- Path: .claude/agents/reviewer.md for this project, ~/.claude/agents/ for all projects
- name: reviewer
- description: Reviews diffs. Use after code changes.
- tools: Read, Grep, Glob
- model: haiku
- The body holds its instructions. It starts fresh and sees only the delegation prompt.

YAML frontmatter, then the instructions. name and description are required.

## Hook events

| Event | Runs | Exit code 2 |
|---|---|---|
| PreToolUse | Before a tool runs | Blocks the action |
| PostToolUse | After a tool runs | Cannot undo it; the tool already ran |
| Stop | When Claude finishes | Sends Claude back to work |

UserPromptSubmit runs when you send a prompt. Configure in settings.json at user, project or local level.

Confirm the event list on the hooks page.

## Advice or enforced?

| Tool | Kind | Use for |
|---|---|---|
| CLAUDE.md, prompts, skills | Advice: Claude decides | Conventions and how-to |
| Hooks | Enforced | Format after every edit; tests before done |
| Deny rules and sandbox | Enforced | Hard allow and deny rules (the docs prefer permissions to hook filters) |

A rule with no exceptions does not belong in CLAUDE.md.

## Run it headless

- claude -p 'run the tests and fix failures' --max-turns 10 --max-budget-usd 2 --output-format json
- -p runs one prompt without a conversation and accepts piped input.
- Limits cap turns and spend.
- The same approach runs in CI through GitHub Actions.

Check the flags with claude --help on your version.

## Skills and MCP in a project

- A project skill lives at .claude/skills/name/SKILL.md.
- disable-model-invocation: true makes a side-effect workflow, such as a release, run only when you type it.
- claude mcp add connects a server.
- Connected servers add their tool names to context even when unused.
- Switch off what you do not need under /mcp.

Every connected server costs context.

## Common mistakes

| Mistake | Why it happens | Fix |
|---|---|---|
| A one-line delegation prompt | A subagent starts fresh and sees only that prompt | Carry the task, the files and the success check |
| A must-hold rule in CLAUDE.md | Claude decides whether to follow it | Use a hook or a permission rule |
| Expecting a hook to undo an action | PostToolUse runs after the tool ran | Prevent with PreToolUse |
| MCP servers left on | Their tool names add to context even when unused | Disable what you do not need under /mcp |

## Cheat sheet

**Know**
- Subagent: own context, scoped tools, returns a summary.
- It sees only the delegation prompt.
- Exit code 2 blocks (PreToolUse) or sends Claude back (Stop).
- CLAUDE.md advises. Hooks enforce.

**Do**
- Write a read-only reviewer subagent.
- Write a hook that blocks a command and one that runs the tests.
- Run claude -p with a turn limit and a budget cap.
- Trim MCP servers under /mcp.
