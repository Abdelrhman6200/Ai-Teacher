## Goal and outcomes

**Goal.** The learner builds a working agent and can choose the right route to build one.

**You will be able to:**
- Define an agent as something that plans its own steps and calls tools in a loop
- Choose among the Client SDK, the Agent SDK, the Claude Code CLI and Managed Agents
- Build an agent with the Agent SDK that has tools, permissions, a subagent and a hook
- Design a small team: a manager and role agents with scoped tools

## Key points

- An agent completes a task by planning its own steps and calling tools that read files, run commands or edit code. The Agent SDK gives you Claude Code's tools, agent loop and context management in Python and TypeScript.
- Four routes. Agent SDK: embed Claude Code's agent in your own app, in a process you operate. CLI: interactive work and one-off tasks. Client SDK: call the API directly and write the tool loop yourself or use the tool runner. Managed Agents: a hosted harness in an Anthropic cloud sandbox or your own.
- The SDK offers built-in tools, hooks, subagents, MCP, permissions, sessions, and skills, commands and memory loaded from .claude folders, plus plugins.
- Third-party products may not offer claude.ai login or rate limits unless approved; use API key authentication. Do not brand your agent as Claude Code.
- Multi-model patterns: an executor that escalates to an advisor, and an orchestrator that delegates bulk work to cheaper workers. Subagents nest three layers deep and run up to 20 at once by default.
- Design one job per agent with scoped tools, outputs written to files, a manager that reads summaries, and a human approval on every external action.

## The agent loop

1. Receive a task.
2. Plan the next step.
3. Call a tool: read a file, run a command, edit code.
4. Read the result.
5. Repeat until the task is done or stopped.
6. Report.

## Common mistakes

| Mistake | Why it happens | Fix |
|---|---|---|
| One agent doing everything | Context grows and errors compound | One job per agent |
| Every agent has every tool | A mistake can reach anything | Scope tools per agent |
| Passing results through chat | They get lost or cut short | Write outputs to files; the manager reads summaries |
| No person on external actions | Errors reach customers | Put approval on every external action |

## Going further

- Pick the route by who runs the loop: Agent SDK (you operate the process), CLI (interactive), Client SDK (you write the loop), Managed Agents (hosted).
- Subagents nest three layers deep and run up to 20 at once by default.
- A third-party product uses API key authentication and must not be branded as Claude Code.
- Record every point where a person had to step in. That list is the improvement backlog.
