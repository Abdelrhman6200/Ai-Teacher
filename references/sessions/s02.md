## Goal and outcomes

**Goal.** The learner picks the right Claude surface for a task and has every account and app set up.

**You will be able to:**
- Name the main surfaces and what each is for
- Map six tasks to the right surface and defend the choice
- Find what is new and what is plan-limited using the release notes

## Key points

- The Claude app on web, desktop and mobile is where most people work. Since 16 September 2026 everything Cowork does is available from any conversation, and Claude Design, Slides and Docs produce designs, decks and documents in any conversation. Artifacts are available on every plan, including Free.
- Claude Code is an agentic coding tool that reads a codebase, edits files and runs commands. It runs in the terminal, IDEs, the desktop app and the web.
- The Claude Platform is for building: the Client SDK calls the API directly, the Agent SDK embeds Claude Code's agent in your own Python or TypeScript app, Managed Agents is a hosted agent harness.
- Rollouts are gradual and many features start in beta or on specific plans, so the release notes are the source of truth for what exists this month.
- Shared and proactive agents are newer surfaces. Claude Tag puts @Claude in a Slack channel as a shared teammate (beta on Team and Enterprise, launched 23 June 2026). Claude Duet is a proactive agent app in research preview, by waitlist for US Pro and Max (21 October 2026), that waits for your approval when it matters. Claude Meetings joins Google Meet calls and builds notes and artifacts (beta on Team and Enterprise, 12 November 2026). Check your plan before you promise any of them.

## Which surface for which job

| Surface | Use it when | Example |
|---|---|---|
| Claude app: web, desktop, mobile | You ask, write, analyse or produce documents, decks and sheets | Summarise a report; draft a deck |
| Delegated tasks (Cowork abilities, now in any conversation) | The work spans several files or apps and runs for a while | Compile a weekly report from a folder |
| Claude Code | The work is in a codebase | Fix a bug in a repository |
| Claude Platform | You build Claude into your own product | A support chatbot inside a company app |
| Shared or proactive agents | The work lives in a team channel, or needs follow-up without being asked | @Claude in a Slack channel; a morning brief |

Keep this table in view during the surface chooser task.

## Three ways to build on the Platform

| Route | What it is | Choose it when |
|---|---|---|
| Client SDK | Calls the API directly; you write the tool loop or use the tool runner | You want full control or one simple call |
| Agent SDK | Claude Code's agent embedded in your own Python or TypeScript app | You want an agent in a process you operate |
| Managed Agents | A hosted agent harness | You want Anthropic to host the loop |

Session 14 returns to these routes.

## Before you promise a feature

1. Open the release notes and find the date of the change.
2. Check whether it is beta or limited to certain plans.
3. Look for it in your own account.
4. If it is missing, assume the rollout has not reached you or your plan excludes it. Do not reinstall.

Features change monthly. Run this check on one feature you have seen in a video.

## Common mistakes

| Mistake | Why it happens | Fix |
|---|---|---|
| Building on the API when the app already does it | Slower and needs engineering | Ask first whether a Project or scheduled task does the job |
| Promising a feature seen in a video | Rollouts are gradual; some features are beta or plan-limited | Check the release notes and your own account |
| One surface for everything | Each is built for a different job | Ask, delegate, build, embed |
| Trusting remembered menu names | Names differ between documentation pages | Navigate from the live interface |

## Going further

- Chats, Cowork tasks, Projects, connectors and skills carry across surfaces, so the question is where the work should run, not which product to buy.
- Use the least engineering that meets the need: chat, then a scheduled task, then Claude Code, then the Platform.
- Read the release notes monthly. Sessions 3 and 16 turn that into a routine.
- Write down the surface choice and the reason, and revisit it when a plan or feature changes.
