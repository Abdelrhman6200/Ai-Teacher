# Session 6: Producing docs, decks, sheets and designs

Level 2: Practitioner (25 to 50). Deliverable: Doc, deck and sheet from one brief. Worth: 6 points.

Contents: Goal and outcomes, Key points, Plain-language glossary, Pick the format, The seven-part brief, filled in, Review order, Worked demo: one brief, three outputs, Common mistakes, Cheat sheet, Exercises, Case to attempt, Vocabulary, Score ladder (what your work looks like at each level), Going further, Study sources, Self-check questions, Exit ticket.

## Goal and outcomes

**Goal.** From one brief, the learner delivers finished work in the right format.

**You will be able to:**
- Choose the format for the job: doc, deck, sheet, design, whiteboard or a plain file
- Write a brief that yields a usable first version
- Edit, iterate and export
- Check content against sources before formatting

## Key points

- Since 16 September 2026 Claude Design, Slides and Docs produce designs, decks and documents in any conversation; artifacts are available on every plan, and some of the new tools are beta on Enterprise.
- Editable docs, sheets, decks, designs and whiteboards can be changed by the person and by Claude in the same file. Docs export to .docx, PDF and Markdown; sheets download as .xlsx. What your account lists varies, so check.
- The pre-built skills create and edit PowerPoint, Excel, Word and PDF files, which is how Claude makes a file in those formats.
- A brief has seven parts: audience, purpose, source material, length, format, what to exclude and the acceptance check.
- Review order: content against the source first, formatting second.

## Plain-language glossary

| Term | Meaning | Think of it as |
|---|---|---|
| Doc | Text you read and edit: memo, report, letter | A page |
| Sheet | A table you sort and calculate with | A ledger |
| Deck | Slides to present | The spine of a talk |
| Design or whiteboard | Something judged by looking, or boxes and arrows to rearrange | A drawing board or a wall of sticky notes |
| Brief | The instruction that carries everything the build needs | The commission |

## Pick the format

| Need | Format | Notes |
|---|---|---|
| Text people read and comment on | Doc | Exports to .docx, PDF and Markdown |
| Numbers to total, sort or compare | Sheet | Downloads as .xlsx |
| A talk | Deck | Edit slides in the same file |
| Boxes and arrows, or a visual layout | Whiteboard or design | Judged by looking |
| A Word, Excel, PowerPoint or PDF file someone asked for | Pre-built skills | Claude creates and edits the file |

What your account lists varies, so check.

## The seven-part brief, filled in

1. Audience: new support agents
2. Purpose: explain how refunds work
3. Source material: the attached refund policy only
4. Length: one page
5. Format: doc
6. What to exclude: legal history, exceptions not in the policy
7. Acceptance check: every rule appears in the policy

The learner writes the same seven parts for their own three outputs.

## Review order

1. Content against the source: every number, name and claim.
2. Structure: order, length, missing points.
3. Formatting.
4. Export, open the file and check it.

Content first, formatting second.

## Common mistakes

| Mistake | Why it happens | Fix |
|---|---|---|
| Polishing before verifying | Well-formatted wrong content travels further | Check content against the source first |
| Asking for a deck with no audience or length | The result is generic | Fill in all seven parts of the brief |
| The wrong format for the job | A story in a sheet, a table in a doc | Read: doc. Sort: sheet. Present: deck. Draw: whiteboard or design |
| Rebuilding to fix one thing | You lose what was right | Ask for the specific edit in the same file |

## Cheat sheet

**Know**
- Read: doc. Sort: sheet. Present: deck. Draw: whiteboard or design.
- Brief: audience, purpose, source, length, format, exclusions, check.
- Content against the source first, formatting second.
- Edit a file in its own format.

**Do**
- Write the seven-part brief.
- Build the doc, the deck and the sheet from it.
- Verify the content, then revise.
- Export in the format the reader needs.

## Exercises

1. One brief, three outputs: a one-page doc, a 6-slide deck and a tracker sheet. Make three revision requests on each, then export each.
2. Edit in the original format. Attach a .docx, ask for its typos to be fixed, and confirm the result comes back as a .docx.

## Going further

- To change a file you already have, edit it in its own format: a .docx attached for typo fixes should come back as a .docx.
- Put the acceptance check in the brief. Decide how you will judge the result before the first draft exists.
- Keep one source of truth and derive the deck and sheet from the doc so the numbers cannot drift apart.
- Check what your account lists. Tools and exports vary by plan and rollout.
