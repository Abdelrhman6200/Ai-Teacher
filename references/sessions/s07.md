# Session 7: Projects, memory and context

Level 2: Practitioner (25 to 50). Deliverable: Working Project for the learner's real job, plus the doc, deck, sheet and verification log from sessions 5 and 6. Worth: 7 points. This is a gate.

Contents: Goal and outcomes, Key points, Plain-language glossary, Where does it belong?, Project instructions, filled in, Reset drill, Memory hygiene, Worked demo: build and test a Project, Common mistakes, Cheat sheet, Exercises, Case to attempt, Vocabulary, Score ladder (what your work looks like at each level), Going further, Study sources, Self-check questions, Exit ticket.

## Goal and outcomes

**Goal.** The learner builds a Project that carries their job context, and knows when to start fresh.

**You will be able to:**
- Distinguish chat history, Project instructions and files, memory, and attached files
- Write Project instructions that hold standing context and output rules
- Decide per task: same chat, new chat or Project
- Review and correct what memory holds, and set memory options deliberately

## Key points

- A Project is a workspace with its own instructions, files and chats. What you put in it is available to every chat inside it.
- Memory builds up across chats and is controlled in Settings (generate memory from chats, search and reference past chats). Each Project also has its own memory setting: connected to account-level memory or separate. Claude cannot switch memory off itself.
- Chats, Cowork tasks, projects, connectors and skills carry over across surfaces after the 16 September change.
- Long chats drift. Start a new chat per task, keep stable facts in Project instructions, and carry state across with a short summary.
- Claude Code applies the same idea: CLAUDE.md is read at the start of every session and auto memory saves learnings across sessions.
- Keep secrets and personal data out of memory and Project files unless needed, and check who a Project is shared with.

## Where does it belong?

| Layer | Holds | Reaches |
|---|---|---|
| Chat | One task's history | That chat |
| Project instructions | Role, audience, tone, output rules, hard limits | Every chat in the Project |
| Project files | Reference documents | Every chat in the Project |
| Memory | What builds up across chats | Set in Settings; each Project has its own setting |
| Attached file | A one-off input | That chat |

Use the learner's own job for each row.

## Project instructions, filled in

- Role: you assist a freelance bookkeeper who serves small clinics.
- Audience: clinic managers, not accountants.
- Tone: calm, plain English.
- Output rules: tables for numbers, list assumptions, mark anything unverified.
- Hard limits: never give tax or legal advice.

Standing facts and rules live here, so they are not retyped in every chat.

## Reset drill

1. Ask Claude to summarise the state in 10 lines: goal, decisions, open items, files, constraints.
2. Read the summary and fix anything wrong.
3. Start a new chat and paste the summary.
4. Ask a question that depends on an early detail to confirm nothing was lost.

Long chats drift. Start a new chat per task.

## Memory hygiene

- Read what memory holds.
- Correct or remove anything wrong or sensitive.
- Set generate memory from chats and search past chats on purpose.
- Check each Project's own memory setting: connected or separate.
- Claude cannot switch memory off itself; the setting is in Settings.
- Check who a Project is shared with.

Menu names change. Check the live Settings page.

## Common mistakes

| Mistake | Why it happens | Fix |
|---|---|---|
| One giant chat for everything | Old text competes for attention | New chat per task, carry state in a short summary |
| One-off facts in Project instructions | They clutter every chat | Keep only standing context there |
| Never reading memory | Wrong or sensitive entries persist | Audit memory; correct or remove entries |
| Secrets in Project files | Anyone with access can see them | Keep them out unless needed and check who it is shared with |

## Cheat sheet

**Know**
- Project: standing instructions, files and chats.
- Memory is set in Settings. Read what it holds.
- New chat per task. Carry state in a short summary.
- No secrets in Project files.

**Do**
- Write the instructions and add three to five files.
- Run three tasks in the Project and in a blank chat, then score.
- Audit memory.
- Run the reset drill.

## Exercises

1. Build a Project for the learner's real role: instructions (role, audience, tone, output rules, hard limits), 3 to 5 knowledge files and a starter prompt.
2. A and B test. Run the same 3 tasks in the Project and in a blank chat and score both.
3. Memory audit. Read what memory holds, correct or remove anything wrong or sensitive, and set the memory and past-chat search options on purpose.
4. Reset drill. Summarise a long chat's state in 10 lines, start a new chat with it and confirm nothing was lost.

## Going further

- A Project's memory can be connected to account memory or kept separate. Decide per Project and be able to say why.
- Claude cannot switch memory off itself. The setting in Settings is the person's, so know where it is.
- The reset drill is a skill: summarise the state in 10 lines, start a new chat and confirm nothing was lost.
- Claude Code applies the same idea with CLAUDE.md, which loads at the start of every session (session 12).
