# Session 1: How AI models work and fail

Level 1: Foundations (0 to 25). Deliverable: Failure log with five entries. Worth: 8 points.

Contents: Goal and outcomes, Key points, Plain-language glossary, How a model produces an answer, Where a model gets its content, Five failure tests, The 4D framework, Worked demo: break it on purpose, Common mistakes, Cheat sheet, Exercises, Case to attempt, Vocabulary, Score ladder (what your work looks like at each level), Going further, Study sources, Self-check questions, Exit ticket.

## Goal and outcomes

**Goal.** The learner can predict where a model is reliable and where it will fail, and checks before trusting.

**You will be able to:**
- Explain next-token prediction in one sentence and say what it implies about errors
- Separate what a model knows (training), what it holds right now (context) and what it is told (instructions)
- Name the five limits: prediction, knowledge, working memory, steerability, context size
- Apply the 4D framework: Delegation, Description, Discernment, Diligence

## Key points

- A model writes one token at a time by predicting what comes next. Fluent does not mean true.
- Knowledge comes from training and stops at a cutoff. The current models list a June 2026 cutoff; anything newer needs search or files.
- Working memory is the context window. The four current API models list 1M tokens, but everything in the window competes for attention, so long chats need managing.
- Steerability: the same model behaves differently under different instructions, which is why the quality of the instruction matters.
- 4D: decide what to delegate, describe it clearly, discern the output, stay diligent about how it is used.
- Anthropic's AI Fluency Index (9,830 conversations sampled in January 2026) found that 85.7 percent of conversations iterate, but only 15.8 percent question the reasoning and 8.7 percent check facts that matter. Iteration is the habit to teach first; Discernment is the gap. Every session in this course closes with a check that starts "now question it".

## Plain-language glossary

| Term | Meaning | Think of it as |
|---|---|---|
| Model | A program trained on a vast amount of text to continue text | A very well-read autocomplete |
| Token | The small piece of text the model reads and writes | A syllable-sized chunk, not always a word |
| Training | The learning stage, which ends at a cutoff date | A student who stopped studying on one day |
| Context | Everything in the chat the model can see right now | The papers open on a desk |
| Instruction | What you ask for and the limits you set | A brief to a new colleague |

## How a model produces an answer

1. Your text is cut into tokens, the small pieces the model reads.
2. The model scores every possible next token and picks one.
3. That token is added to the text, and the model repeats until it stops.
4. Nothing in this loop checks whether the result is true.

Draw the loop on the board. Ask: what is the loop optimised for? Plausible next text, not truth.

## Where a model gets its content

| Source | What it is | Typical failure |
|---|---|---|
| Training | Patterns learned up to the cutoff | Misses anything newer; states old facts as current |
| Context | Everything in the chat now: messages, files, results | Loses a detail from the middle of a long document |
| Instructions | What you tell it to do | Vague request, generic answer; contradictory request, a coin toss |

Three branches, the memory hook. Name one failure of each from your own experience.

## Five failure tests

| Test | What it shows |
|---|---|
| Ask for a source, then check it exists | Prediction: it writes what a citation looks like |
| Ask about a recent event with search off, then on | Knowledge: training stops at a cutoff |
| Paste a long document, ask about a detail in its middle | Working memory and context size |
| Give two contradictory instructions | Steerability: it follows the instructions it is given |
| Ask a leading question with a false premise | Prediction: it continues the premise instead of challenging it |

These are the five tests of the live task. 

## The 4D framework

| D | The question | Example |
|---|---|---|
| Delegation | Should AI do this task, and which part? | Draft the email: yes. Decide whether to drop a client: no. |
| Description | Have I said what, for whom and what good looks like? | Audience, goal, format and limits stated. |
| Discernment | Is the output right and fit for use? | Check a claim against the original source. |
| Diligence | Am I answerable for what I send or publish? | Verify before sending; keep private data out. |

Place each step of your last AI task under a D.

## Worked demo: break it on purpose

Run this yourself on your own material.

| Step | Do this | What it shows |
|---|---|---|
| 1 | Ask for three sources on a narrow topic, then open each one | Real-looking titles may not exist: it predicts, it does not look up |
| 2 | Ask about an event after the cutoff with search off, then on | The answer changes because the source changed, not the model |
| 3 | Paste a long document and ask about a detail in its middle | A long window is not perfect recall |
| 4 | Ask a question with a false premise built in | It tends to continue the premise instead of challenging it |

## Common mistakes

| Mistake | Why it happens | Fix |
|---|---|---|
| Treating fluent as true | A confident tone can hide a guess | Ask for the source, open it, compare |
| Asking vaguely | The model fills each gap with the likeliest guess | State audience, goal, format and limits |
| One endless chat | Old text competes for attention | New chat per task, carry a short summary |
| Sending unchecked | The draft looked finished, so diligence was skipped | Verify the claims that matter before it leaves |

## Cheat sheet

**Know**
- A model predicts the next token. Fluent is not true.
- Training stops at a cutoff. Context is what it sees now.
- A long context is not perfect recall.
- 4D: delegate, describe, discern, be diligent.

**Do**
- Run the five failure tests and log each one.
- Name the limit behind each failure.
- Sort ten tasks: delegate, co-work or keep.

## Going further

- Reliability belongs to the task, not the model: the same model is strong at summarising text you gave it and weak at recalling an obscure figure.
- Before delegating, ask what a wrong answer would look like here and how you would notice it.
- Match the check to the stakes: spot-check a draft, verify every number in a contract summary.
- Keep the failure log. Patterns across entries show which tasks to stop delegating.
