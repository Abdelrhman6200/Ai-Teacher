# Session 9: Skills

Level 3: Builder (50 to 75). Deliverable: Two tested skills with their trigger matrix and baseline scores. Worth: 6 points.

Contents: Goal and outcomes, Key points, Plain-language glossary, A skill folder, A SKILL.md, part by part, Which tool for the need?, A trigger matrix, Test and measure, Worked demo: a weekly status skill, Common mistakes, Cheat sheet, Exercises, Case to attempt, Vocabulary, Score ladder (what your work looks like at each level), Going further, Study sources, Self-check questions, Exit ticket.

## Goal and outcomes

**Goal.** The learner writes skills that trigger reliably and measurably improve the output.

**You will be able to:**
- Decide whether a need calls for a skill, Project instructions, a connector or just a prompt
- Write a SKILL.md with valid frontmatter and a trigger-ready description
- Add a reference file and a script, then test triggering
- Package, install, share, and review third-party skills for safety

## Key points

- A skill is a folder whose only required file is SKILL.md; references, assets and scripts are optional.
- name: lowercase letters, numbers and hyphens, up to 64 characters, matching the folder name, without the words anthropic or claude. description: what the skill does and when to use it, up to 1,024 characters. Claude reads it to decide when to load the skill.
- Progressive disclosure: name and description are always loaded (about 100 tokens each), the SKILL.md body loads when triggered, other files load only when a step needs them. Keep SKILL.md under 500 lines.
- Use a skill for a task repeated the same way. Do not use one for a one-off, for live data (a connector) or for instructions that apply to every conversation (preferences or Project instructions).
- Scripts run by path with the skill folder placeholder; never put credentials inside a skill, since everyone you share it with receives the files.
- Package by zipping the skill folder itself so the archive's top level is the folder, then upload under Customize, then Skills. In Claude Code, place it in ~/.claude/skills/ or a project's .claude/skills/.
- Where a skill is available depends on where you added it. The platform docs say custom skills do not sync between claude.ai, the API and Claude Code; the claude.com docs say items added in claude.ai load in Claude Code when signed in to the same account. Test on your own setup.
- Test: validate the frontmatter, send prompts that should trigger it and check Claude's thinking, revise the description, then measure with the skill-creator skill, which in Cowork and Claude Code also runs a baseline without the skill and reports pass rates, timing and tokens.
- Security: use only skills you wrote or that come from Anthropic, and read every file of any other skill before use.
- Keep references one level deep from SKILL.md, and give any reference file over 100 lines a table of contents. Write evaluations before the instructions: run three or more representative tasks without the skill, record the baseline, write the minimum that closes the gaps, then compare. Test on every model you will use, since Haiku may need more explicit guidance and Opus may be over-explained.

## Plain-language glossary

| Term | Meaning | Think of it as |
|---|---|---|
| Skill | A folder of instructions Claude loads when the task fits | A recipe card Claude reaches for |
| SKILL.md | The one required file: a name, a description, then the steps | The card itself |
| Description | Says what the skill does and when to use it | The title that decides if it gets picked |
| Reference and script | Optional files that load or run only when a step needs them | The appendix and the tool drawer |

- weekly-status-report/ the folder; its name matches the skill name
- SKILL.md the only required file
- references/ optional detail Claude reads when a step needs it
- assets/ templates and examples
- scripts/ optional code, run by path

Progressive disclosure: name and description always load, the body loads when triggered, other files load when a step needs them.

## A SKILL.md, part by part

| Part | Example | Rule |
|---|---|---|
| name | weekly-status-report | Lowercase letters, numbers, hyphens; up to 64; matches the folder; no 'anthropic' or 'claude' |
| description | Writes the weekly status report in the team format. Use when asked for a weekly update or status report. | What it does and when to use it; up to 1,024 characters |
| body | Steps, the format, a pointer to the template | Under 500 lines |

Claude reads the description to decide when to load the skill.

## Which tool for the need?

| Need | Use |
|---|---|
| A task repeated the same way | A skill |
| Live data from an app | A connector |
| Instructions for every conversation | Preferences or Project instructions |
| A one-off task | A prompt |

Skills are for repeated procedures only.

## A trigger matrix

| Prompt | Should the weekly skill fire? |
|---|---|
| Write this week's status report | Yes |
| Draft the weekly update for the team | Yes |
| Summarise this email | No |
| What did we ship last week? | Ambiguous: decide, then fix the description |

The learner writes five yes, five no and three ambiguous prompts per skill.

## Test and measure

1. Validate the frontmatter.
2. Send prompts that should trigger it and check Claude's thinking to see whether it loaded.
3. Revise the description in the words a request would use.
4. Measure with the skill-creator skill: baseline run without the skill, pass rates, timing, tokens.
5. Read every file of any third-party skill before use.

Only use skills you wrote or that come from Anthropic.

## Common mistakes

| Mistake | Why it happens | Fix |
|---|---|---|
| A vague description | Claude cannot tell when to load the skill | Name the task and the phrases that trigger it |
| A skill for a one-off or for live data | No repeat, or the data goes stale | Use a prompt, or a connector for live data |
| Credentials inside a skill | Everyone you share it with gets the files | Never put credentials in a skill |
| Installing a third-party skill unread | Its files and scripts run with your access | Read every file before use |

## Cheat sheet

**Know**
- SKILL.md needs a name and a description. Keep it under 500 lines.
- The description says what it does and when to use it.
- Name and description always load. The rest loads on demand.
- No credentials inside. Read a third-party skill first.

**Do**
- Pick a task you repeat.
- Write the skill and test the trigger: 5, 5 and 3 prompts.
- Run a baseline with and without it.
- Package it.

## Exercises

1. Pick two repeated tasks. Skill A is instructions only, such as a weekly report format. Skill B adds a reference file and a template or script.
2. Trigger matrix. Write 5 prompts that should trigger each skill, 5 that should not and 3 ambiguous ones. Record hits and misses and fix the description until the clear cases are right.
3. Baseline test. Run 3 real prompts with and without each skill and score both.
4. Security review. Read one third-party skill end to end and list every file, command and network call it touches.

## Going further

- Progressive disclosure keeps context cheap: name and description are always loaded, the body loads when triggered, other files load when a step needs them.
- Keep SKILL.md under 500 lines and move detail into reference files.
- Measure the lift: run real prompts with and without the skill and compare scores. The skill-creator skill runs the baseline in Cowork and Claude Code.
