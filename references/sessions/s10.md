# Session 10: Plugins, Cowork and scheduled work

Level 3: Builder (50 to 75). Deliverable: A packaged plugin and one scheduled recurring task with its failure check. Worth: 6 points.

Contents: Goal and outcomes, Key points, Plain-language glossary, What a plugin holds, Install a plugin safely, Where should it run?, Before it runs unattended, Worked demo: a Monday report, Common mistakes, Cheat sheet, Exercises, Case to attempt, Vocabulary, Score ladder (what your work looks like at each level), Going further, Study sources, Self-check questions, Exit ticket.

## Goal and outcomes

**Goal.** The learner packages skills and connectors into a plugin and runs recurring work without being present.

**You will be able to:**
- Explain what a plugin bundles and where each component works
- Install, disable, remove and update a plugin safely
- Build and share a small plugin
- Create a scheduled task and decide where it runs

## Key points

- A plugin packages skills, MCP connectors, commands and agents as one unit, added from Customize, then Plugins, by Discover, Add marketplace or Upload plugin. An uploaded archive must hold one .claude-plugin/plugin.json.
- Skills, commands and connectors work in chat, Cowork and Claude Code. Agents work in Cowork and Claude Code.
- Adding a plugin does not connect its connectors. Open its Connectors tab to connect each one. Its skills load either way.
- Directory plugins get automated validation and a security scan, and a person reviews new listings. That review does not cover a marketplace URL or an upload, so add those only from sources you trust. In Cowork and Claude Code, agents and hooks can run commands on your computer.
- Create a plugin with Claude or by writing its files, then share it with specific people or publish it to the organisation on Team and Enterprise.
- Claude Code schedules work three ways: cloud scheduled tasks run in the cloud even when your computer is off and can trigger on a schedule, an API call or a GitHub event; desktop scheduled tasks run on your machine with your local files; /loop repeats a prompt inside a CLI session.
- Unattended work needs clear success criteria, read-only access first, approvals defined, and a report someone reads.

## Install a plugin safely

1. Customize, then Plugins, then Discover, Add marketplace or Upload plugin.
2. List its components and what each can touch.
3. Open its Connectors tab and connect each one. Adding the plugin does not connect them.
4. Add a marketplace URL or an upload only from sources you trust; they skip the directory review.
5. Keep or remove.

In Cowork and Claude Code, agents and hooks can run commands on your computer.

## Where should it run?

| Option | Runs | Use for |
|---|---|---|
| Cloud scheduled task | In the cloud, even with your computer off; by schedule, API call or GitHub event | A daily report; event-driven work |
| Desktop scheduled task | On your machine with your local files | Work that needs local files |
| /loop | Repeats a prompt inside a CLI session | Watching something while you work |

Place four of your own recurring jobs.

## Before it runs unattended

1. Write the success criteria.
2. Start read-only.
3. Define which actions need approval.
4. Send the result where someone reads it.
5. Write the failure check: what tells you it did not run or ran wrong.

An unattended task nobody reads is a silent failure.

## Common mistakes

| Mistake | Why it happens | Fix |
|---|---|---|
| Assuming install means connected | Connectors need their own sign-in | Connect each one from the Connectors tab |
| Installing from an unknown source | Directory review does not cover URLs or uploads | Add those only from sources you trust |
| Scheduling a write action first | A mistake repeats unattended | Start read-only, then add approvals |
| No failure check | Silent failure looks like success | Name who reads the report and what a missing one means |

## Cheat sheet

**Know**
- Plugin: skills, connectors, commands and agents.
- Installing does not connect its connectors.
- Schedule on the cloud, on the desktop or with /loop.
- Unattended work: read-only first, approvals, a report someone reads.

**Do**
- Package two skills and one connector.
- Install it on a second account and connect.
- Schedule a read-only task and run it once by hand.
- Write the failure check.

## Going further
