# Session 17 quiz: Context engineering and prompt caching

Contents: Q1 to Q10, fill in the blank, matching.

Ask one question at a time. Show the stem and options only. Hold the key until the learner has answered. Do not repeat a question in the same sitting.

## Q1

A cached prefix stops hitting after you add a timestamp at the top of the system prompt. Why?
- A. The cache matches the prefix in order, so a changed early block invalidates everything after it
- B. Timestamps are blocked by the API
- C. The cache expires after one call
- D. The model forgot the prompt

Key: A. Why: Put volatile content after the cached blocks.

## Q2

Where should per-request values such as the user message and the time go?
- A. After the cached blocks, at the end
- B. First in the system prompt
- C. Inside the tool definitions
- D. Anywhere: order does not matter

Key: A. Why: The cache hashes tools, then system, then messages, in that order.

## Q3

What does a cache hit require?
- A. Any similar prompt
- B. The same user
- C. A smaller model
- D. A prefix that matches a recent request exactly, up to the breakpoint

Key: D. Why: The cache hashes the prefix in order.

## Q4

Where do timestamps and per-user text belong?
- A. After the cached blocks, at the end
- B. First in the system prompt
- C. Inside the tool definitions
- D. They never matter

Key: A. Why: Volatile content placed early invalidates the cache.

## Q5

What is the default cache lifetime?
- A. 24 hours
- B. 5 minutes, refreshed on each hit
- C. One request
- D. 30 seconds

Key: B. Why: A 1-hour lifetime costs more to write.

## Q6

An agent's old tool results fill the window. Which fits?
- A. A longer system prompt
- B. Lower effort
- C. Context editing to clear old tool results
- D. Deleting the tools

Key: C. Why: Clearing drops re-fetchable results but keeps the record of the call.

## Q7

Facts must survive across separate sessions. Which fits?
- A. A bigger max_tokens
- B. Prompt caching
- C. Streaming
- D. The memory tool: files outside the window

Key: D. Why: Memory is stored in files that persist.

## Q8

A side task would flood the main context with search results. What helps?
- A. A sub-agent with its own context that returns a summary
- B. Pasting everything in
- C. Turning off tools
- D. Raising effort

Key: A. Why: Sub-agents keep the noise out of the main window.

## Q9

How do you confirm that caching works?
- A. Wait for the invoice
- B. Read cache_creation_input_tokens and cache_read_input_tokens in usage
- C. Ask Claude
- D. Check the model name

Key: B. Why: Measure, do not assume.

## Q10

Why can clearing tool results raise the cost of a call?
- A. It deletes the system prompt
- B. It disables caching
- C. It changes the prefix, so the cache is rewritten at that point
- D. It switches the model

Key: C. Why: Clear enough tokens at once to make the rewrite worthwhile.

## Fill in the blank

- A cache read costs about ____ times base input on most models. Key: 0.1
- The cache matches the prompt in order: tools, system, then ____. Key: messages

## Matching

Match each term to what it means.

- Context rot = Accuracy falls as the window fills with noise
- Compaction = A summary replaces older turns
- Memory tool = Files that persist across sessions
- Cache breakpoint = The point up to which a prefix is cached
