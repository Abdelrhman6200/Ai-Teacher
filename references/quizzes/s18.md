# Session 18 quiz: Reasoning control, structured outputs and tool design

Contents: Q1 to Q10, fill in the blank, matching.

Ask one question at a time. Show the stem and options only. Hold the key until the learner has answered. Do not repeat a question in the same sitting.

## Q1

A response ends with stop_reason max_tokens during heavy reasoning. What are the two fixes?
- A. Raise max_tokens if the reasoning was needed, or lower effort if the task was over-thought
- B. Add more tools
- C. Turn on caching
- D. Lengthen the system prompt

Key: A. Why: Thinking and the answer share the max_tokens ceiling.

## Q2

Which control is the calibrated first step for reasoning depth?
- A. A line in the system prompt
- B. The effort setting
- C. A fixed thinking budget
- D. The temperature

Key: B. Why: Set effort first. Prompt guidance only if triggering still does not match.

## Q3

Which setting controls thinking depth?
- A. temperature
- B. A fixed budget_tokens value
- C. The length of the system prompt
- D. output_config.effort

Key: D. Why: Effort replaced fixed budgets on the newest models.

## Q4

What is effort?
- A. Soft guidance on how often and how deeply Claude thinks
- B. A hard token budget
- C. A model name
- D. A billing tier

Key: A. Why: Use max_tokens for the hard cap.

## Q5

Why hold effort constant inside a conversation?
- A. It is forbidden
- B. Changing it between requests can invalidate the prompt cache
- C. It changes the model
- D. It resets the memory

Key: B. Why: Per-message effort in beta keeps the cache.

## Q6

A program parses Claude's reply as JSON. What is the safest design?
- A. Ask nicely in the prompt
- B. Retry until it parses
- C. Enforce the schema with structured outputs
- D. Lengthen the prompt

Key: C. Why: Constrained decoding makes the JSON valid.

## Q7

Forced tool choice (any or tool) returns an error on a model. What now?
- A. Switch to a retired model
- B. Remove the tool
- C. Raise effort
- D. Use auto with strict tool use or structured outputs

Key: D. Why: Strict tool use guarantees valid inputs.

## Q8

Which tool-description detail matters most?
- A. What it does, when to use it, when not to, and what it returns
- B. The author's name
- C. The date
- D. The logo colour

Key: A. Why: The description is the largest lever on tool performance.

## Q9

Two tools overlap and the agent keeps picking the wrong one. What fixes it?
- A. Add a third tool
- B. Merge or rename them and retest on real requests
- C. Hide the descriptions
- D. Raise max_tokens

Key: B. Why: Fewer, clearly separated tools are chosen more reliably.

## Q10

Responses stop with max_tokens while reasoning. What are the options?
- A. Ignore it
- B. Turn off the tools
- C. Raise max_tokens if the reasoning was needed, or lower effort if it was over-thought
- D. Switch to batch

Key: C. Why: Thinking and the answer share the max_tokens ceiling.

## Fill in the blank

- Effort is set in output_config.____. Key: effort
- Strict tool use is turned on with strict: ____. Key: true

## Matching

Match each setting to what it does.

- max_tokens = Hard cap on thinking plus answer
- Effort = Soft guidance on how much Claude thinks
- Structured outputs = Schema-valid JSON by construction
- Tool description = What the agent reads to choose a tool
